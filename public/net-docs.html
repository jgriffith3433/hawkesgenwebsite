Quickstart

Your players' pages hold no secrets, so a page never asks for a room directly. Your server asks hawkesgen.com for a ticket with your API key (above), hands it to the page, and the page joins with it. A ticket is good for one join, for 90 seconds; the SDK asks your route again when it needs another (reconnecting, moving to the relay).

1Your ticket route

Any server will do. Decide who may join which room (your logins, your matchmaking), then forward the request with your key. Rooms are yours alone: nobody else's game can join them.

// Node (Express); the same in any language: one HTTPS POST with your key.
app.post('/ticket', async (req, res) => {
  const r = await fetch('https://hawkesgen.com/v1/net/rooms/ticket', {
    method: 'POST',
    headers: { Authorization: `Bearer ${process.env.HAWKESGEN_KEY}`, 'Content-Type': 'application/json' },
    body: JSON.stringify({ room: req.body.room, name: req.user.name, sub: req.user.id }),
  });
  res.status(r.status).json(await r.json());
});

Keep the key on your server. sub is your own id for the player (the same person reconnecting keeps their place).

2Join in the page

import { join } from 'https://net.hawkesgen.com/sdk/hawkes-net@1.mjs';

const ticket = () => fetch('/ticket', {
  method: 'POST', headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ room: 'lobby' }),
}).then((r) => r.json());

const net = await join('lobby', { ticket });

net.on('chat', (text, from) => show(from.name, text));
net.send('chat', 'hello');                        // reliable: once, in order

net.pose([x, y, z], yaw);                          // your avatar, as often as you like
net.onPose((peer, s) => moveAvatar(peer, s.p, s.y));

net.when('peer:join', (p) => addAvatar(p.id, p.name));
net.when('peer:leave', ({ peer }) => removeAvatar(peer.id));

One ES module, no build step, no dependencies. Prefer a copy? Save hawkes-net.mjs and hawkes-net-core.mjs side by side and import your copy.

3Unity WebGL

The com.hawkes.net package runs the same SDK in the page and gives you a C# room. Point ticketUrl at your route from step 1.

var room = HawkesNet.Join("lobby", new HawkesNetOptions { ticketUrl = "https://mygame.example/ticket", name = "Ada" });
room.OnReady += r => Debug.Log($"in {r.Name} over {r.Transport}");
room.On<Chat>("chat", (msg, from) => Show(room.Peers[from], msg.text));
room.Send("chat", new Chat { text = "hello" });

void Update() {
    room.Pose(player.position, player.eulerAngles.y);
    foreach (var kv in room.Poses) MoveAvatar(kv.Key, kv.Value.position, kv.Value.yaw);
}

WebGL builds only. Ask us for the package while it waits for its Asset Store listing.

Rooms and transports

A room is any name you choose (letters, digits and / _ . -, up to 64). The first ticket for a name opens it. transport on the ticket picks how it travels:

transportWhat happensUse it for
auto (default)Peer to peer while small (one player hosts, the others link to them). Past p2pMax players, when the host leaves, or when links fail, the room moves to our relay on the same connections.Friends' rooms, invites, small matches
relayThrough our relay from the start. Interest by distance and a byte budget per player keep it light.Public rooms, big worlds, anything with more than a handful
p2pPeer to peer only; the room is full at p2pMax.Two to eight players who never need the relay

Peer-to-peer traffic never touches our servers. net.transport says where a room is now, and net.when('transport', …) tells you when it moves (you don't need to do anything).

Messages and avatars

CallWhat it does
net.send(kind, data, opt?)To everyone. Reliable by default (once, in order, across reconnects and moves). { reliable: false } may drop; { to: peerId } sends to one; { self: true } includes you.
net.on(kind, (data, from, meta) => …)Messages of one kind; '*' for all.
net.pose([x, y, z], yaw, extra?)Your avatar. Call it every frame; the newest goes out about 15 times a second, compressed.
net.onPose((peer, state, at) => …)Everyone else's avatar: state.p, state.y and your extras.
net.when(event, fn)status, ready, peer:join, peer:leave, host, transport, problem.
net.now()The room's shared clock, in milliseconds.
net.leave()Out of the room (closing the tab does it too).

Shared state

net.sync keeps things in step: one player simulates each moving thing (its owner, or the host), and everyone else sees it smoothly.

net.sync.push(id, [x, y, z, rx, ry, rz, vx, vy, vz])A thing you simulate
net.sync.onThing((id, at, values, from) => …)Things others simulate
net.sync.claim(id) / hold(id) / release(id)Take a thing over (a grab, a car you drive); a held thing stays yours
net.sync.state(name, data)A shared document (a score, a door); joiners get its newest copy

Reference: POST https://hawkesgen.com/v1/net/rooms/ticket

With Authorization: Bearer hg_… (your key). JSON body:

Field
roomRequired. The room's name.
nameShown to the others (24 characters).
subYour id for this player (64 characters).
transportauto (default), relay or p2p.
roleplayer (default) or spectator (watches; doesn't count toward the room's size).
configThe room's shape when this ticket opens it: maxPlayers (up to 64), p2pMax (up to 8), profile (light, medium, heavy: how much a room sends), sendHz.

The answer is what join() takes from your ticket function as it is: ticket, peer, relayUrl, transports, expiresAt, …. Errors: 401 no key or a wrong one, 402 your account can't use Hawkes Net yet (below), 409 the room is full, 429 too many rooms or tickets.

Limits and pricing

  • Up to 64 players a room; up to 8 peer to peer before the relay.
  • Hawkes Net for your own games is open to accounts that have bought credits or a plan.
  • While we set prices, using it costs no credits. Your usage is counted above (player-minutes and relay data) so you'll see what you'd pay before you pay anything.
